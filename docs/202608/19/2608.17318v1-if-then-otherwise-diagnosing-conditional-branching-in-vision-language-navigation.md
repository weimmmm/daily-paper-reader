## 摘要
视觉语言导航智能体通常根据其遵循指向固定目标的路线式指令的能力进行评估。然而，真实的导航指令往往依赖于环境的状态观察：如果某个条件成立，则走一条路，否则走另一条路。这类指令要求智能体评估场景证据，选择正确的逻辑分支，并执行相应的导航行为。现有评估对条件分支执行的控制有限，难以确定智能体失败的原因究竟在于感知、接地、导航还是逻辑决策。我们提出了CondVLN，一个基于场景图的条件分支诊断基准，用于视觉语言导航。CondVLN程序化生成指令，其分支条件基于可验证的3D场景图谓词，并在分支深度、依赖链长度、空间组合、证据可观察性和指令范围方面进行受控变化。CondVLN包含跨越AI2-THOR、Matterport3D、Gibson和ReplicaCAD的超过11,500条生成的条件指令，并使用标准VLN指标和分支特异性诊断（分支选择准确率和条件成功率）来评估智能体。对四个最先进的VLN智能体（VLN-Zero、NaVid、NaVILA和Open-Nav）的评估表明，条件分支暴露了仅凭标准成功率或路径长度无法捕获的失败：智能体可以在合理导航的同时，选择与观察到的场景条件不一致的分支。我们还提出了一个轻量级神经符号分支选择模型，将条件接地与导航执行分离，将性能提升了2倍。CondVLN提供了一个可复用的测试平台，用于衡量具身智能体是否不仅能遵循指令，还能在正确条件下遵循正确的指令。

## Abstract
Vision-language navigation agents are often evaluated on their ability to follow route-like instructions toward a fixed goal. Yet, real navigation instructions often depend on observed states of the environment: if a condition holds, then follow one path, otherwise take another. Such instructions require an agent to evaluate scene evidence, select the correct logical branch, and execute the corresponding navigation behavior. Existing evaluations provide limited control over conditional branch execution, making it difficult to determine whether agents fail because of perception, grounding, navigation, or logical decision-making. We introduce CondVLN, a scene-graph-grounded benchmark for diagnosing conditional branching in vision-language navigation. CondVLN programmatically generates instructions whose branch conditions are grounded in verifiable 3D scene-graph predicates, with controlled variation in branch depth, dependency chain length, spatial composition, evidence observability, and instruction horizon. CondVLN contains over 11,500 generated conditional instructions across AI2-THOR, Matterport3D, Gibson, and ReplicaCAD, and evaluates agents using standard VLN metrics and branch-specific diagnostics: Branch Selection Accuracy and Conditional Success Rate. Evaluating four state-of-the-art VLN agents (VLN-Zero, NaVid, NaVILA, and Open-Nav) shows that conditional branching exposes failures that are not captured by standard success rate or path length alone: agents can navigate plausibly while committing to a branch inconsistent with the observed scene condition. We also present a lightweight neurosymbolic branch-selection model that separates condition grounding from navigation execution, improving performance by 2x. CondVLN provides a reusable testbed for measuring whether embodied agents can not only follow instructions, but follow the right instruction under the right condition.

- 视觉语言导航（VLN）的主流评测基准（如 R2R、RxR 等）主要考察智能体能否沿着路线式指令到达固定目标，重点在线性指令跟随与目标到达。

  - 理解自然语言中的条件结构；

  - 执行对应的具体导航行为。
- 现有评测无法对“条件分支”进行系统控制，当智能体失败时，也难以判断失败来自感知、语言接地、导航执行还是逻辑决策。
- 针对这一空白，论文提出 **CondVLN**：一个基于 3D 场景图的、可程序化生成条件指令的基准，旨在把“条件推理”作为 VLN 中显式、可控的评测维度，从而诊断具身智能体在“正确条件下执行正确指令”上的能力。

## 2. 论文提出的方法论

### 2.1 核心思想

- 将环境信息抽象为**分层 3D 场景图**，把物体-物体、物体-房间的空间与语义关系表示为符号谓词。
- 基于场景图**程序化生成条件导航指令**，使每条指令的每个分支条件都对应可验证的、真实的 3D 场景谓词。
- 通过控制**分支深度（嵌套层级）** 与**链长度（连续条件分支数）** 来调节任务逻辑复杂度，从而支持细粒度的失败定位。

### 2.2 关键流程

整个框架分为“数据集生成”和“评测”两大部分：

1. **场景层次统一表示（Scene Hierarchy）**：
   - 将 AI2-THOR、Matterport3D、Gibson、ReplicaCAD 等异构数据源的语义与几何信息转换为统一格式。
   - 每个房间包含对象节点，对象带有语义标签、3D 中心坐标、可选的包围盒/半径等几何元数据。

2. **语义与空间关系生成（Semantic and Spatial Relationship Generation）**：
   - 对同一房间内的对象对计算中心距离、水平距离、AABB 表面距离等度量。
   - 生成**规范方向谓词**（8 方位角 + 上/平/下），并生成**语义谓词**（near/far、higher/lower、above/below）。
   - 最终形成带可追溯度量信息的对象-对象、对象-房间关系图。

3. **条件指令合成（Conditional Instruction Synthesis）**：
   - 从场景图采样“有效参考对象”和“无效条件对象”（即不存在于当前房间但存在于场景其他位置的对象），从而构造真/假分支。
   - 同一房间内同名对象用空间限定词消歧。
   - 指令模板支持多种逻辑结构：
     - 简单 IF-ELSE；
     - 嵌套 IF（IF 内部的 IF）；
     - 多层嵌套；
     - IF / ELSE IF 链；
     - 长链多分支；
     - 嵌套 + 链式。

4. **转换为 VLN-CE 兼容评测片段（Dataset Realization）**：
   - 将场景图中的坐标转换到 Habitat 坐标系；
   - 使用 Habitat-Sim 路径搜索计算最短路径；
   - 生成 R2R/VLN-CE JSON 格式的 episode（含场景 ID、起始与目标位姿、指令文本、参考路径、测地距离等）；
   - 因此无需修改模拟器即可用于 VLN-Zero、NaVid 等现有框架。

### 2.3 新增评测指标

- **分支选择准确率（Branch Selection Accuracy, BSA）**：
  - 衡量智能体按顺序完成了多少正确的分支子目标（允许部分分数），用于捕捉“分支选择是否正确”，而不要求最终到达终点。
- **条件成功率（Conditional Success Rate, CSR）**：
  - 要求既完整执行正确分支（BSA=1），又达到最终目标（标准 Habitat 成功），即对“条件任务”的严格成功标准。

### 2.4 神经符号分支选择 Oracle 基线

- 论文设计了一个轻量级 **oracle 基线**：在评测前利用数据集构建时记录的符号信息，直接确定正确分支，并把条件指令改写为线性导航指令（例如将“if … go to A; otherwise go to B”改写为“go to B”）。
- 该基线用于诊断：如果逻辑分支已正确解析，下游导航执行能力会怎样变化；从而将“逻辑分支选择”与“感知/导航执行”解耦。
- 实现时只改指令文本，不改变 episode 的目标、路径或环境，因此与原始条件设置的差异主要由“去除分支选择难度”造成。

## 3. 实验设计

### 3.1 数据与场景

  - **Matterport3D (MP3D)**（真实扫描室内场景）；

- 指令覆盖 6 种复杂度类别（Simple、Nested、Deep Nested、Chain、Long Chain、Nested Chain）。

### 3.2 评测智能体

评估了四个代表不同建模框架的 SOTA VLN 方法：

- **VLN-Zero**：基于场景图推理的零样本方法；
- **NaVid**：基于视频的 VLM 导航方法；
- **NaVILA**：足式机器人视觉-语言-行动模型；
- **Open-Nav**：基于开放 LLM 的零样本导航方法，具时空链式推理。

### 3.3 评测设置

- 使用统一的 VLN-CE 兼容接口；
- 动作预算与指令长度成比例；
- 成功距离阈值：ReplicaCAD 为 0.5m，其他多房间数据集为 1.0m；
- 不提供额外分支注释，智能体必须从自然语言中推断条件并自行决策。

### 3.4 实验设计维度

- 主实验：在 4 个数据集上报告 SR、SPL、BSA、CSR；
- 复杂度扫描：
  - 逻辑深度扫描（d=1, 2, 3）；

- 通过以上受控变量，分析性能退化主要由“嵌套深度”还是“链长度”驱动；
- Oracle 基线实验：验证去除符号分支选择难度后模型性能的变化。

## 6. 论文的主要结论与发现

1. **现有 VLN 智能体在条件分支上表现显著下降**：
   - NaVid、NaVILA 在多数条件下 CSR 很低甚至为 0；
   - Open-Nav 和 VLN-Zero 相对更强，但仍在复杂条件下明显退化。
2. **标准指标不足以诊断条件导航失败**：
   - 智能体可能获得不低的 SR/SPL，但 BSA/CSR 更低，说明“到达一个貌似合理的终点”并不等同于“选择了正确分支”。
3. **复杂度增加、性能系统下降**：
   - 无论增加嵌套深度还是链长度，BSA 和 CSR 均下降；
   - 不同模型对两种复杂度轴的敏感度不同，表明该基准能区分“层级推理”与“长序依赖”两类困难。
4. **显式符号推理在复杂条件下更有效**：
   - Oracle 基线在 d=3、ℓ=1 和 d=1、ℓ=2 等困难设置下显著优于 Open-Nav 和 VLN-Zero，性能约提升 2 倍；
   - 表明将“条件接地”与“导航执行”解耦的神经符号方法，对复杂条件导航具有重要价值。

## 7. 优点

- **问题定位准确**：直击 VLN 评测中“条件分支逻辑”缺失的痛点；
- **基准构建可验证、可控制**：
  - 所有条件都来自场景图中的符号谓词，真值已知，可进行确定性验证；
  - 程序化生成支持对嵌套深度、链长度、空间关系等进行精确控制；
- **与现有生态兼容性好**：直接输出 VLN-CE 格式 episode，可无缝用于现有评测框架；
- **诊断性指标有针对性**：BSA 与 CSR 能区分“分支选对但没走到”和“完全选错分支”等不同失败方式；
- **神经符号 Oracle 作为诊断工具设计巧妙**：不改变导航模块，只消去分支选择难度，从而把逻辑推理与感知/执行分离，便于归因分析；
- **环境多样性好**：同时覆盖合成（AI2-THOR、ReplicaCAD）与真实扫描（MP3D、Gibson），检验迁移性和异构场景表达能力。

## 8. 不足与局限

- **只覆盖室内场景**：评测限定在 VLN-CE 兼容的室内环境，无法推广到室外、开放世界或更复杂局面的条件导航。
- **底层数据与注释噪声**：MP3D、Gibson 等扫描数据存在语义标注噪声，可能影响条件验证与感知接地结果的公平性。
- **空间关系生成依赖固定几何启发式**：阈值和谓词计算方式可能在特定场景分布或环境类型下失效，泛化性有限。
- **Oracle 基线过于理想化**：
  - 它在评测时直接使用数据集构建期间记录的符号真值，实际智能体必须从视觉观测中推断条件；
  - 因此 Oracle 的“2 倍提升”不能直接当作可部署方法的性能，只能作为理论上限或诊断工具。
- **训练/微调视角缺失**：所有模型均为零样本或预训练后固定，未验证在 CondVLN 上进行训练或微调能否带来更大提升；
- **缺少更细致的性能分解**：对“感知错误 vs 逻辑错误 vs 执行错误”的归因仍主要依赖指标设计，而非细粒度行为分析；
- **计算资源与可复现性说明不足**：未提供算力、运行时间、代码仓库等详细信息，实际复现和扩展门槛较高。
